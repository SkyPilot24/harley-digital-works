## Root causes and implemented corrections

1. **Deployment configuration missing:** Cloudflare has no public build configuration or server credentials. Intake now refuses missing or inconsistent browser/server backend URLs. Production configuration must be explicitly restored against the verified intended backend, after staging acceptance.
2. **Bypass and bootstrap:** current Lovable database still has an anonymous/ordinary lead INSERT policy, one administrator, enabled first-admin signup trigger and no attempt table. Ported the isolated forward hardening migration, preserving roles/leads and administrator manual intake. Revoked excessive table grants including TRUNCATE/TRIGGER/REFERENCES. No live attack submissions were made.
3. **Concurrency:** separate count/insert and duplicate-check/insert requests raced. New service-role-only, SECURITY INVOKER RPC acquires transaction locks in a fixed order, records quota and persists/deduplicates atomically. DB clock governs timing/window checks. Invalid timing consumes quota; failed insert rolls back. Anonymous/ordinary/admin callers cannot directly execute this RPC; legitimate administrators retain their authorised manual entry path.
4. **IP trust:** only the Cloudflare-overwritten `cf-connecting-ip` is used; forwarded headers cannot rotate the fallback bucket. Any directly exposed non-Cloudflare origin must strip that header or use the shared unknown bucket. This is bounded abuse control, not bot-proofing; client timestamps and a honeypot remain heuristics.
5. **Notification safety:** Slack requires `LEAD_NOTIFICATIONS_ENABLED=true`. Staging keeps it and transactional email false, with no outbound credentials. Existing save-before-notify handling survives notification failures. A durable retry/outbox is still outstanding under H09; no delivery claim is made.
6. **Retention:** traffic-dependent deletion removed; restricted `prune_lead_submission_attempts()` can run without new enquiries. Hourly scheduler remains an explicit setup action, not a completed retention guarantee.
7. **Inherited function grants:** staging advisor exposed inherited PUBLIC execution missed by historical role-specific revokes. Follow-up migration removes public role-probing RPC access and locks down the optional provider-created RLS event-trigger function. Private policy helper still serves administrator checks.
8. **Dependencies:** minimal updates within existing constraints clear the two critical advisories (Seroval and shell-quote), plus source-map-js. Nine moderate/high findings remain in development tooling; no framework/wrapper upgrade was performed. Assess before release. Raw advisory evidence is in `docs/evidence/dependency-audit.json`.
