## Small daily routine

1. Read root [AGENTS.md](../AGENTS.md), the opening [status brief](../PROJECT_STATUS.md) and newest task-relevant [handover](HANDOVER.md). Identify repository/path, branch, exact HEAD, dirty files and owning review checkout. Do not assume main has the latest peer work.
2. Retrieve only needed [business](../BUSINESS_DEFINITION.md), [backlog](../MASTER_BACKLOG.md), [offer](COMMERCIAL_OFFER_MANAGED.md), [brand](brand-pack.md) and evidence/source sections. Expand history to resolve a specific dependency or contradiction. Do not load both full libraries by default.
3. Derive up to three weekly priorities from actual recorded blockers and founder decisions; distinguish proposed goals from approved commitments. Recompute when evidence changes, rather than carrying an old weekly list indefinitely.
4. Recommend exactly one next action with task ID, owner, blocker, approval needed and empirical completion criterion. If blocked, identify the smallest useful unblocked preparation.
5. Before coding search existing routes/components/helpers/tests, Git history and active checkpoint/worktree. State what is reused and the exact missing behaviour. Do not rebuild useful existing features or repeat accepted integrations. Preserve peer work.
6. Load only task-relevant canonical skills through [shared skills](SHARED_SKILLS.md). Run checks appropriate to the change; preserve founder judgement and exact external-action boundaries.

### Reconciled task skeleton

Role: task-specific reviewer/builder within current scope.
Inputs: exact task, owning source/branch, approved facts/assets, relevant checkpoint and acceptance criteria.
Method: inspect/reuse existing implementation; identify one gap; make the smallest reversible change; verify affected behaviour.
Output: concrete result/reviewable change, observed evidence and limits, decisions/approvals needed and one next action.
Quality: source-backed facts, no duplicate feature, invented success, new commercial commitment or implied external permission.
