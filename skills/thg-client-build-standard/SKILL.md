# THG Client Build Standard

## Start with the actual project

Read repository instructions, existing business definition, status, backlog and handover where present. Identify audience, approved offer, primary conversion, existing brand/design system, current stack and deployment. Preserve useful work; do not require a framework migration. For another client, use that client's approved facts and commercial terms, not Harley's proposed pricing.

Inspect existing pages and real interactions before proposing replacement. Select a small representative page set and reusable templates. Establish a clear page hierarchy: customer problem, specific offer, credible evidence, scope/process, objections and one primary next action. Use secondary CTAs only where they serve a distinct need.

## Design and content

Produce a deliberate visual system: coherent type scale, spacing, colours, components, imagery and interaction states. Avoid generic section repetition, excessive decorative effects and inconsistent controls. Judge the actual rendered result on mobile and desktop, including long content, empty and error states. Use brand-appropriate licensed imagery; optimise sizes and reserve image space.

Use verified customer facts, approved claims and supplied rights-cleared assets. Never invent reviews, accreditations, people, jobs, client logos, guarantees or results. Label demos clearly. Distinguish proposed price/terms from approved publishable terms. Place conversion CTAs where they answer the user's intent; keep forms short, labelled, honest about next steps and resilient to errors.

## Acceptance is functional

Test navigation, contact paths, submitted data, thank-you/error states and authorised retrieval. Notification failure must not silently lose a saved enquiry. Do not present unfinished tools as functioning services. Preserve domain/email ownership and existing working integrations.

Target WCAG 2.2 AA using semantic structure, labels, keyboard operation, visible focus, readable contrast, usable touch controls and reduced motion. Automated scanning is not full conformance proof. Verify unique page titles/descriptions, canonical domains, crawl controls, sitemap and factual structured data. Check loading behaviour, image/fonts/JavaScript cost and layout stability on realistic devices/connections; a lab score is not field performance.

Keep shared components and templates maintainable; reuse validation and content models. Apply project-specific security checks to forms, auth and data access. Run applicable repository checks and browser journeys; report untested environments. Use THG Production QA for requested release readiness, and THG Supabase Security for relevant database/auth work when available.

## Automated delivery with quality review

Design the normal path as enquiry, qualification, approved-template proposal, provider-confirmed payment, onboarding, templated build, automated QA, customer approval, launch and recurring care. Use one customer record and durable stage/next-action/exception tracking. AI output is a draft; rules and evidence control transitions. Include retries and deduplication.

During the first pilot, validate critical transitions and founder-review launch outputs. Once rules are validated, standard cases advance automatically within approved limits. Retain selected founder quality reviews, mandatory novel/high-risk review and explicit customer approval. Do not require the founder to approve every routine proposal or build. Exceptions must explain cause, impact, owner and recovery action.

Record setup and support effort, quality failures and interventions so the pilot proves repeatable economics rather than unpaid founder administration. Refer to the project's revenue workflow where present; do not activate billing, outreach or deployment merely because the plan mentions it.

## Handover

Update the existing task/status record with changed behaviour, acceptance evidence, remaining defects, inspected and released revisions, and exact next action. Separate implemented, tested and deployed. Keep access credentials and customer personal data out of general documentation. A visually polished preview alone is not a completed client service.
